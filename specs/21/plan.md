# Implementation Plan: #21 Implement feature Invite to Workspace

**Branch**: `feat/21-invite-to-workspace` | **Date**: 2026-11-27 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/21/spec.md` (Trello card #21), per-screen specs `../specs/017-invite-to-workspace/spec.md` (WEB-D11) and `../specs/005-workspace-members/spec.md` (WEB-05, User Story 4 only), screen specs `../docs/ui-pipeline/screens/WEB-D11-invite-to-workspace.md` and `WEB-05-workspace-members.md`, mockups `WEB-D11-invite-to-workspace.html` and `WEB-05-workspace-members.html`.

## Summary

Card #21 is the sender side of workspace invites. The recipient side (Pending invites on Home with `Accept` / `Decline`, card AC 3 and 4) already shipped with card #6 (`InviteList.tsx`, `POST /invites/:id/accept|decline`). This card only adds regression checks for it.

New on the frontend:

1. **WEB-05 Members page shell** (today a placeholder): workspace title, an `Invite` button, the `Sent invites` table (Email, Role, Status, Expires, `Resend`, `Revoke`; hidden when empty), a red banner above the title for failed `Resend` / `Revoke`, and the toast "Invite sent". The member table, member count, role change, remove and the workspace menu belong to card #8 (Workspace Members) and are not built here (research R1).
2. **WEB-D11 Invite dialog**: `Email` plus a `Role` select (`Member` by default), `Cancel` / `Send invite`, inline errors for an invalid email, an existing member and an existing pending invite, a spinner labelled "Sending invite", a failure banner inside the dialog, and closing on success with a toast.
3. **API client + hooks** for the four sender endpoints defined by the backend #21 plan (`agi-board-backend/specs/21/contracts/invites.md`), mirrored in [contracts/api-client.md](contracts/api-client.md) (R2).
